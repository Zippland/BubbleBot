# Agent 与消息协议

[返回 README](../README.md)

本文面向希望修改工具或消息行为的开发者。工具定义见 [bubbles/agent/tools/](../bubbles/agent/tools/)，Agent 循环见 [loop.py](../bubbles/agent/loop.py)。

## 从输入到执行

渠道把入站消息转换为统一事件。Agent 根据 session 绑定加载历史、SOUL、MEMORY 和技能索引，调用配置的模型；模型选择工具，工具结果回填，循环继续到本轮结束。

同一个 session 串行处理，避免并行修改同一份历史。不同 session 可以并发；进行中的轮次也可以接收新消息，在后续工具调用前交给模型作为补充。

## 三个消息相关工具

| 工具 | 作用 | 是否结束本轮 |
| --- | --- | --- |
| `switch_message_target(channel, chat_id)` | 切换当前发送窗口，保存到 session。 | 否 |
| `message(content, ...)` | 发送正文或附件，使用当前目标，不另传地址。 | 否 |
| `stay_silent()` | 结束本轮；已经发过消息也可以调用。 | 是 |

`stay_silent` 的语义是 end turn，不要求整轮沉默，也不是取消已发生的操作。与它同批返回的其他工具仍会执行并保留结果。

普通 assistant 文本（包括工具前的说明）与 `message` 走同一发送路径。模型可以说，也可以不说；框架不要求工具前必须加一句话。思考内容不作为群消息发送。

## 目标与回执

- session 首次运行时用触发聊天初始化发送目标，之后只有显式切换才改变，跨轮和重启保留。
- 切换目标不改变工作空间、历史归属或定时任务定义。
- 同一响应的普通文字先于工具执行发送，因此发往新窗口时应先单独切换、查看结果，再说话。
- 每次发言向模型返回实际目标和提交状态，失败时附原因；回执不重复正文，也不另发到群里。
- 提交到发送队列，不等于平台已经确认送达。

## 固定工具定义，运行时检查条件

主 Agent 的内置工具集合不随是否配置生图、cron 或渠道管理器而增减。未配置后端时，由调用结果说明原因。系统触发的轮次仍能看到 `cron`，但执行会被拒绝，避免递归调度。

MCP 工具由连接的服务发现；后台 subagent 使用自身的工具集合，不能把主 Agent 的全部能力视为自动继承。

## 配置、调试与安全

使用 `uv run bubbles agent -s personal --debug` 可检查工具和系统提示词；不要公开含私人上下文的调试输出。
